# V2A REAL / BingX physical qualification — preregistration

Date: 2026-09-21

## Scientific purpose

Test whether BingX Spot can serve as a **new, exact, prospective-only physical source candidate** for the already-canonical asset identity `REAL / reallink` after the currently admitted MEXC Spot `REALUSDT` route produced a live `no_candle` / HTTP 400 failure in the V2A PIT collector.

This is source qualification only. It does not replace MEXC, amend the canonical qualified registry, repair the current PIT snapshot, backfill history, grant D0/scientific/prospective credit, alter the universe denominator, or feed any engine.

## Frozen identity

- canonical symbol: `REAL`
- canonical asset / coin id: `reallink`
- candidate provider: `BINGX_SPOT`
- exact candidate pair: `REAL-USDT`
- base asset: `REAL`
- quote asset: `USDT`
- market: spot
- timezone/cutoff semantics: UTC daily candles, no future rows

Independent identity support available before the run:

1. QRDS adjudication PR #474 identifies canonical asset as `REAL / reallink`.
2. BingX currently exposes a product page specifically for buying **RealLink (REAL)** through `REAL/USDT` spot.
3. CoinGecko currently lists BingX `REAL/USDT` as a RealLink market.

The API qualification itself must still fail closed if exact pair/status/candle evidence is not available.

## Frozen physical checks

The run must capture raw bytes and SHA-256 for:

1. BingX spot symbol response from `/openApi/spot/v1/common/symbols` filtered to `REAL-USDT`;
2. BingX public historical daily kline response from `/openApi/market/his/v1/kline` for `REAL-USDT`;
3. normalized accepted candles up to UTC cutoff `2026-09-20`.

The exact API pair must be uniquely present and active (`status=1`). Candles must satisfy:

- non-empty returned corpus;
- strictly increasing unique timestamps after normalization;
- no OHLC invariant violations;
- no negative base/quote volume;
- no accepted row after the frozen cutoff;
- deterministic raw hashes recorded.

Because this is only physical qualification, **historical coverage sufficiency is not asserted**. A short but valid corpus may still pass physical qualification.

## Frozen disposition

A clean run may only produce:

`ELIGIBLE_FOR_SEPARATE_PROSPECTIVE_ONLY_ADJUDICATION`

It does **not** authorize source substitution.

A failure produces:

`FAIL_CLOSED_SOURCE_OR_PARSE_ERROR` or `FAIL_CLOSED_FULL_CORPUS_QA`

No endpoint, pair, provider, asset identity, cutoff, QA rule, or safety boundary may be changed after observing the outcome except for a demonstrably mechanical API-schema correction that does not alter the scientific question.
